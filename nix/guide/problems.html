Rift guide

If something goes wrong

Check the drive and the services first

rift doctor

It looks at the drive, the slot you booted from, the free space on your volume, and each of the system's own services, and prints a line for each.

Read the log

journalctl -b -p warning
journalctl --user -b -u lens

The first is what the system said this boot, warnings and worse. The second is the desktop shell by itself.

The desktop is stuck

The shell brings itself back a second after it stops, so a bar or a dock that has gone is usually back before you have read this. If the session itself is stuck, Ctrl, Alt and Delete ends it and starts it again, and anything you had open is closed with it.

The machine does not start from the drive

Check that Secure Boot is off in the firmware settings, and that the firmware is set to UEFI rather than legacy boot. A drive that starts on one machine and not on another is almost always one of those two.

Reporting it

Problems are tracked at github.com/officialthomasguthrie/Rift/issues. A report of how Rift runs on a particular machine is worth as much as a bug, and this writes one:

rift doctor --report > report.md

It says what the machine is, how long it took to start, every device in it, and what the checks above found. Add what worked and what did not, and send it with the report.
