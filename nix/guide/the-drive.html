Rift guide

The drive

Everything Rift is lives on one drive. Plug it into a computer that starts from USB, and you have your own system on that machine; take it out, and the machine is as it was.

What is on it

The drive has two parts that are kept apart on purpose.

The system is a read-only image. It is checked block by block as it is read, so a block that has been changed is refused rather than used. Nothing you do can write to it, which is also why an app is never installed into the system itself.

Your side of the drive is an encrypted volume. Your files, your settings, the apps you install and the AI models all live there. It is unlocked with your passphrase, and without that passphrase the drive is a box of random bytes.

There is also a plain partition, called exchange, that Windows, macOS and Linux can all read. Use it to hand a file to a computer that knows nothing about Rift. It is at /exchange, and Files lists it in the sidebar. It is not encrypted, so keep out of it anything you would not leave on a memory stick.

Starting up

Turn the computer on and pick the drive in its boot menu. The key for that menu is usually F12, F11, F9 or Esc, depending on the maker. Rift needs UEFI firmware, and for now Secure Boot has to be off.

The first boot of a new drive makes the encrypted volume and asks you to set its passphrase. Every boot after that asks for the passphrase and nothing else.

Ghost mode

Ghost mode is a second way to start the same drive. It leaves the encrypted volume locked, puts your home folder in memory and writes nothing to the drive at all. When you shut down, the drive is exactly as it was and the session is gone.

Every boot starts with a menu of two lines, shown for three seconds:

Rift 0.1.0
Rift 0.1.0 (Ghost mode)

Leave it alone and the first line starts, which is the ordinary boot. Press a key to stop the countdown, pick the second line with the arrow keys and press Enter for Ghost mode. It asks for no passphrase, because there is nothing to unlock. You get a working Rift with none of your files, none of your settings, no apps you installed and no AI models. Anything you make in it lives in memory until the machine is turned off.

Use it to lend the computer to somebody, to open something you would rather leave no trace of, or to check that the drive still starts when you have forgotten what you changed.

The exchange partition is the one part of the drive a Ghost session reaches. Nothing mounts it there on its own, because mounting it writes to it, and a session that keeps nothing has to keep that promise about the plain partition too. Files lists it in the sidebar as a place that is not mounted; select it and it is mounted, and you can hand a file to another computer from a session that keeps nothing else. What you put there is on the drive afterwards, because you asked for it.

What a Ghost session cannot do, it says. Anything that reads or writes the drive answers with one sentence naming the mode, rather than failing on a missing file or saying there is nothing there. That is rift ai, which has no models to run; rift snapshot and rift backup; rift host auto-unlock, rift host keys, sudo rift host enroll-key and sudo rift clone, which all need the drive's passphrase; and in Settings the Owner page, Backups, Updates, the models on the AI page and the boot style on the Appearance page. Each of those says the mode in the place the row would be. What you set in a Ghost session that does work, such as the wallpaper, an app you install or which app opens a kind of file, holds until the machine is turned off and is on no drive afterwards, and the foot of the Settings sidebar says so on every page.

A Ghost session says which mode it is in. The right end of the top bar reads Ghost mode for as long as you are logged in, and a notification at the login says what that means; it stays on screen until you close it. rift doctor says it over its rows, and the rows it explains, such as the one for the encrypted volume, pass rather than fail. Rift Welcome does not open in Ghost mode, because nothing it sets would be kept; you can still open it from the Applications menu, and its first page says so.

Starting without the passphrase on your own machine

On a machine that is yours, Rift can put a key for the volume in that machine's TPM, the small chip most computers made since about 2016 have for holding keys. The drive then starts on that machine with nothing typed.

Tell Rift the machine is yours, then turn it on:

rift host set class owned
rift host auto-unlock on

It asks for the drive's passphrase once, because that is what the key is made from. After that, rift host auto-unlock on its own says what the drive does at boot, and rift host auto-unlock off takes the key away again.

Two things to know. One machine holds the key at a time: turning it on on a second machine takes it off the first. And the passphrase never stops working, on that machine or any other, so the drive is still yours anywhere.

What this costs you: somebody who takes both the drive and that machine can start it. Without the machine, the drive is a box of random bytes as before. Use it on a computer that stays where you are, and leave it off for a drive you carry.

A security key

A FIDO2 security key can unlock the volume in place of the passphrase. Unlike the TPM, the key belongs to the drive and not to a machine, so it works wherever you plug the drive in, and you can enroll as many keys as you own. Two is the usual number: one you carry and one you keep somewhere safe.

Plug the key in and run:

sudo rift host enroll-key

It asks for the drive's passphrase, because that is what the key is added beside, then asks for the key's own PIN and waits for you to touch it. At every boot after that the drive asks for the key's PIN and a touch instead of the passphrase. If the key has no PIN set, a touch is all it asks.

rift host keys lists the keys that open the drive, each by the keyslot it uses, and rift host remove-key takes one off by that number. Both are also on the Owner page in Settings, which is where you can see what opens the drive without typing anything.

The passphrase never stops working, with a key enrolled or without one, so losing a key does not lose the drive.

The computer you are borrowing

Rift uses the machine's processor, memory, graphics, screen and network. It does not touch the machine's own disks: they are never mounted by themselves, and nothing is written to them. The firmware of the machine is read and never written, for the same reason.

Rift remembers each machine it has run on, by the identifiers its firmware reports, and keeps a profile for it on your volume: the screen scaling, the graphics path and the size of AI model that fits its memory. The second time you boot on a machine, it is already set up.
